Transactions & Workflows

Approval workflows put people between a change and its effect. Setting one up means defining the steps, deciding who approves, and triggering it at the right time.

Quiz this topic

Key concepts

  • Workflow object. The Workflow foundation object defines approval steps, approver types, contributors and CC roles.
  • Approver types. Role, Dynamic Role, Dynamic Group, Position and Position Relationship.
  • Role codes. E = employee, EM = employee's manager, EMM = manager's manager, EH = employee's HR representative.
  • Dynamic role vs. dynamic group. A dynamic role resolves to a person or position from the employee's data, e.g. the HR partner for a location. With a dynamic group, any one member of the group can approve.
  • Contributors and CC. Contributors are notified during the workflow and can comment but don't approve. CC roles are notified once it's complete.
  • Approver edit options. No Edit, Edit with Route Change, Edit without Route Change.
  • Triggering. A Trigger Workflows rule assigned onSave to the HRIS element decides which workflow starts.
  • Admin tools. Manage Workflow Requests lets admins find pending requests and reassign, approve or lock them, e.g. when an approver has left.

Common traps

  • A dynamic group needs one approval, not all members'.
  • Workflows don't start by themselves — a derivation rule triggers them.
  • CC roles don't see the request until it's completed.

Practice tasks

Do these in a practice or demo instance. Each one ends with how to prove the outcome, just like in the exam.

Two-step promotion approval

Outcome: A promotion entered by a manager needs approval from the manager's manager and then from HR for the employee's country.

Hints
  1. Create a workflow with step 1 = EMM and step 2 = a dynamic group or dynamic role for HR.
  2. Create a Trigger Workflows rule for the promotion event reason and assign it onSave to jobInfo.

Prove it: Submit a promotion, show the pending request with both steps, approve it and show the change in Job History.

Approval for address changes

Outcome: Address changes made in self-service go to HR for approval.

Hints
  1. Assign a workflow derivation rule onSave to the homeAddress element.

Prove it: Change an address as the employee and show the pending request.

Unstick a request

Outcome: A pending request whose approver left is moved to a new approver.

Hints
  1. Use Manage Workflow Requests to find and reassign it.

Prove it: Show the request with the new approver in the workflow details.
